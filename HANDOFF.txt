2. ARCHITECTURE (how a question is answered)
======================================================================================================================
Browser -> Vercel Next.js routes (/api/chat/stream etc., same-origin proxy) -> Render FastAPI (query_server.py)
  1. smalltalk? ("hi", "thanks", "what can you do") -> canned reply, no retrieval, no LLM.
  1b. guard.py: canned replies (self-harm, privacy, injection, homework) with no LLM; follow-up rewritten by followup.py
  2. answer cache hit? L1 memory then L2 Supabase (6 h; 10 min for date-dependent; never cached without sources, degraded, follow-up or grade-specific answers)
  3. retrieval (rag.py), in parallel:
       a. embed the question with the Supabase Edge Function `embed` (gte-small, 384-d)  [source: supabase/functions/embed]
          then vector search RPC match_chunks_v2 on table document_chunks_v2 (24 candidates)
       b. structured calendar lookup (intent.py parses dates / sport / gender / home-away / A-B-day / advisory) on metadata
       c. link cards (booking/payment) and direct teacher/course lookup (entity_chunks) from school_courses records
     then a hybrid lexical+vector rerank (no ML on the server; 32 candidates, tuned weights, stale docs demoted, optional FTS) -> pinned KEY FACTS + top 5 docs + calendar block -> context
  4. Groq chain: openai/gpt-oss-120b -> openai/gpt-oss-20b -> qwen/qwen3.8-27b (the ONLY chat models this Groq key can use;
     llama-3.3-70b does NOT exist for it). max_retries=0; on 429 it moves to the next model, waits once, then (new) returns a DEGRADED answer
     built from retrieved calendar lines/facts/links with an honest note instead of an error. Streaming SSE to the browser (meta -> delta* -> done with suggestions).
  5. analytics events (anonymous anon_id + session_id) go to Supabase table analytics_events via /api/track.
WHY no ML on the server: Render free = 512 MB; bge-large + reranker needed ~1.6 GB and was OOM-killed. Server now uses ~75 MB.
Hugging Face Docker Spaces were rejected by the user (paid). Stay on free plans; ask before suggesting anything paid.
